# 测试、验收与部署

本规范叠加在 AGENTS.md、既有 release baseline 守卫、业务规则和部署安全规则之上，不替代它们。工程通过、用户认可、合并、部署和来源启用分别记录。

## Review 材料

- Issue/方案版本/用户实施授权证据、分支、完整提交、PR、与目标分支的差异范围。
- 已实现行为、未完成项、已知限制及对应验收标准。
- 必要测试的命令、环境、代码版本、结果与日志位置；失败/跳过不能记通过。不无理由重跑无影响的大套件。
- 涉及业务页面时提供真实浏览器实机材料及可访问业务链接，区分真实数据与隔离测试数据；不得以模拟页面替代真实业务验收。纯文档/模板任务注明浏览器业务演示不适用，并进行相应语法、链接、权限与平台验证。
- 涉及数据时证明身份、来源、数量口径、幂等、失败保留和恢复；只凭 HTTP 200、截图或计数不算闭环。
- 回滚准备与兼容性检查。无数据库或运行环境变更时明确写“不涉及”，不编造验证。

## 合并与 staging

按仓库保护规则通过必需检查和审查；合并需要用户授权，不能绕过保护、必需审查或审批。最终验收前 PR 只用非关闭引用，合并不自动关闭 Issue。

部署须有独立明确的用户授权，注明候选版本及环境。检查 Actions/合并是否会触发生产；无法限定 staging 时在触发前停止并提供证据。准备部署前版本、数据/附件备份及恢复路径，检查迁移、环境配置、权限、后台任务及唯一采集 owner，不泄露凭据。部署后核对实际运行版本及代表性真实业务链、登录/RBAC、失败恢复，不能把首页打开当交付。

无部署内容的任务可以在 Review 完成最终验收后进入 Done，记录 Staging 不适用及用户确认，不能为填状态擅自部署。此配置任务仅创建 PR；Issue Form 正式入口测试须在用户批准并合并后进行。

## 最终交付和关闭

逐项对照该版本验收标准，记录用户最终确认、实际运行环境/链接/版本、测试和部署证据、后台运行方式、限制与后续需求。用户确认达到约定标准后才将 Status 设 Done 并关闭 Issue。只交付局部、存在外部阻塞或仅历史可读时保留准确状态及恢复点，不假完成。

Parked 保留暂停原因/恢复条件；Won't Do 保留用户不实施决定/理由。不能以“长期没更新”自动关闭真实事项。

## 本次基础设施的验证边界

1. 本地解析三份 YAML，校验唯一 ID、合法字段、可选输入、分类标签与链接。
2. 检查 Project、字段/选项/视图和当前权限；字段 ID/选项只使用现场读值。
3. 建立明确 TEST Issue 并加 product，观察自动加入及 Idea，保存自动化证据前不能手动添加或改状态。未成功按故障记录，不掩盖。
4. 自动化确认后只用该测试项验证必要状态写权限，随后关闭测试 Issue、移除该测试卡片；保留验证记录，不删除历史。不修改真实需求/PR。
5. PR 合并后，通过实际 Issue Form 再测标签与自动化，测试项同样清理；合并前不能宣称这一步通过。
