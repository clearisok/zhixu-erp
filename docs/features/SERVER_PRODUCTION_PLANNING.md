## 数据与业务边界

- `SalesOrder → production_schedule_assignments[]`，不恢复ProductionPlan层。
  服务端核实可信合同或已消费加工批次及当前有效归属；没有报价采用、认领或负责人前置。
  完成/取消订单不接新计划变更，历史重复只读。加工订单没有伪艾诺科资料。
- 计划数量为精确非负小数字符串，允许零；与来源数量、客户DeliveryPlan及未来完成量独立。
  超排展示警告，不禁止合法混合执行，不自动调整客户需求或颜色配额。
- 内部生产组与外发厂二选一。新建/更换执行方采用启用的完整资源链；同一执行方普通编辑
  保留已采用资源事实，停用后仍可读、修改说明及取消。明确队列重排才采用最新日历。
- 日期必须显式提供，无“今天”默认。内部按既有特殊日期/交接日公式计算；固定人工日期
  不当作已计算日历，首次生产日和非工作日数量保持null。外发只有固定日期。
- 工期采用原ceil规则，以BigInt对小数精确求整；不把大数量转成JS number。工期上限36600
  工作日、计算总预算36600扫描日、每组/每订单最多500记录，超界明确失败，不截断成功。
- 新增/修改/取消仅涉及该条计划；后续可能需重排时提示。明确重排预览涵盖完整组队列及
  所有受影响订单，固定日期保护，顺序真正按sequence/createdAt/id。6C前没有实际执行事实；
  纯内核对开工/完成保护已单独测试，不冒称当前HTTP已开放实际完成。
- 无外发裸单价、客户工价、销售价、币种或换汇字段。不以报价工价推算外发采购费用。

## 身份、快照与历史

`0035`只加新表，不回填。独立订单集合版本、生产组队列版本和单条Assignment版本CAS；
每次计划变更必须在同一事务追加精确版本。SQL逐事件验证，即使一事务多次编辑，也不能
只留下最后版本或事后补造旧版本。取消不删除身份、历史或日志。

资源完整规范化事实按SHA256去重并不可变，含名称、父子关系、工作周和全部例外日期；
不能仅以master ID/version代替。快照首次记录时间不是某张计划的采用时间，采用证据在
Assignment版本、actor/request和审计。主数据改名/停用/换日历不重算旧计划。

颜色复用0028的SO+规范化颜色名身份，数量/交期/整行来源hash变化不重建颜色ID。
共享非金额helper也供原商业读取使用，当前有效来源持有单可与执行SO不同，创建的稳定
身份仍属于执行SO。重名/无法唯一识别的新颜色阻断；已有身份保留历史并要求预览核对，
不猜改名，不按重复名第一行汇总。整单计划可不指定颜色。

归一盘点登记四个新SO引用，并关联哈希完整计划版本、资源快照、成功命令回执和当前
队列头。已知拒绝回执不产生执行事实、没有成功订单桥接，不能称全部操作历史已纳入；
仍在原actor/request范围可读。新增Server计划不把外部生产/财务覆盖从unavailable冒称已验证，
也不授权订单归一执行或搬移计划。

## 事务与并发

首版用一个事务级排单写锁串行化跨组变更，保留全部CAS及完整预览指纹，不能只凭锁保存。
顺序为有效归属共享fence → fresh用户/角色锁 → actor/request → 排单写锁 → 资源共享scope →
所有受影响有效组的物理SO按UUID锁定 → 读取/冻结事实 → 保存。物理SO包括历史source owner。
正常来源writer先取父行KEY SHARE，SQL镜像/颜色/link/交期触发器也遵守父冻结，防止删色/插色竞态。
资源CRUD在同一资源scope取独占锁，计划冻结取共享锁，先scope后资源行，避免角色和资源锁反序。

预览使用一致性只读事务；提交重新计算完整预览并比较指纹。指纹包含精确意图、actor身份、
订单/颜色/客户需求、队列集合/版本、全部变更及完整新资源事实。无自由actor、价格或完成字段。
版本不符、资源/来源/队列已变化时保存已知拒绝回执，不执行部分变更。未知SQL/审计失败整体回滚。
同一请求重复返回原结果；换内容相同请求冲突；未知/待定仅查原请求，不自动POST。

## API与权限

唯一入口 `/api/v1/production-scheduling`，只接可信Server session，无Browser回退。

| 方法/路径 | 行为 |
| --- | --- |
| POST `/preview` | 精确解析create/update/cancel/replan意图，返回差异、警告、版本及previewHash；不写库 |
| POST `/commands` | requestId + 同一intent + previewHash；同事务版本/审计/回执，已知拒绝返回原404/409 |
| GET `/commands/:requestId` | 当前actor的known/pending/unknown和原内容hash；不能据unknown自动重发 |
| GET `/orders/:id` | 非金额订单/稳定颜色/客户交期需求及计划、资源摘要和当前可操作性 |
| GET `/groups/:id` | 有界完整当前队列及队列版本 |
| GET `/assignments/:id?offset=0` | 当前计划、完整已采用资源及50条/页不可变历史 |

读取同时要求order.view和schedule.view；预览/提交create另需schedule.create，其余需schedule.edit。
每次服务从DB刷新身份/权限，写命令锁住用户、角色和授权直到提交。回执也重验对应操作权限。
没有新grant或隐式管理员；不因生产权限获得任何成本/金额。POST继续同源/CSRF边界、1MiB正文；
预览、回执及读取超过1MiB明确失败，不泄漏原始数据库异常。操作复用唯一OperationLog。
