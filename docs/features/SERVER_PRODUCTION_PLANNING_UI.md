# Server排单页面接线

2026-10-20；D-147 Gate6B，延续[计划后台](SERVER_PRODUCTION_PLANNING.md)与[读取契约](SERVER_PRODUCTION_PLANNING_READS.md)。
这是既有排单页面的Server owner实现，不是Browser数据迁移、实际生产完成、物流或关账。
工程结果与应用源码按[Gate6任务](../tasks/active/server-convergence-gate6-2026-10-20.md)的独立记录核实。

## 入口和职责

`/production-scheduling`先通过authority wrapper选择owner。Server不挂载Browser排单、订单、资料或款式进度repository；
旧Browser页面和长期namespace不改。仅恢复已存在的生产排单菜单，需要order.view和schedule.view。
未开放经营工作台、关账或未实现的Server物流。新目标空库无默认生产组、地点、日历或订单Seed。

保留原生产组MasterDetail、队列表格、订单池、表单及Foundation弹窗/抽屉。
生产组按Server有界全局排序分页，停用但有计划仍显示；队首是计划顺序，不冒称已经开工。
订单池按真实已排量先筛选再分页，空格搜索为且。历史/冻结订单不当作新候选；已有计划仍可读。
订单排单抽屉同时显示内部和外发记录，取消只追加状态，不删除历史。
实际完成与物料/物流暂未纳入，明确说明，不显示虚假的零或“无风险”。

## 表单和确认

- 数量、日产量保留十进制字符串；工期复用现有精确ceil规则，不经JS number转换业务数量。
- 新建执行方、计划日期需要明确输入。订单剩余量未知保持空；剩余为零禁用“全部可排数量”。
- 当前重复颜色只显示名称与待核对，不以第一行数量冒充颜色合计；新分配阻断，已有历史身份保留。
- 修改保持单条/订单集合版本与采用资源名称。主资料改名或停用不自动覆盖历史日历；明确重排才采用最新资源。
- 取消和重排也先预览；等待期间禁用输入。整组预览说明各订单/颜色、前后数量/日期、采用资源与警告。
- 资料变化时已知拒绝后可重新读取订单，保留输入，再产生新的明确预览；不会自动重排后续或更改客户需求。
- 保存后重新读取当前列表；成功回执只是发生时快照，不把它当当前列表。

## 会话和未知结果

每个异步调用绑定整个可信session对象的lease；失效、换用户或A→B→A均不能接收旧响应、清新缓存或用旧401退出新会话。
原actor/tab最多一条未核对命令，缓存只用独立Server请求namespace；缺失/损坏不回退Browser或内存、不静默删除。
提交前先持久保存原requestId/intent/previewHash；双击只发送一次。未知、摘要不符、撤权、网络失败均保留原字节。

恢复先明确点击“核对原请求”。只有GET已证明unknown，且仍是同一session与同一缓存命令，才显示单独“重试原请求”。
重试沿用全部原字节，不换编号、不重新预览、不自动POST；pending、查询失败或摘要不符时不提供重试。
新登录必须重新核对，不能继承旧unknown许可。已验证applied/rejected且内容hash匹配才确认移除原缓存。
导航、具体“查看订单”按钮、返回/登出继续使用现有Server保护，未保存可确认放弃，未核对结果不能绕过。

## 可核对的领域拒绝

预览后队列容量、扫描预算或响应预算可能变化。execute在已鉴权/请求锁和SAVEPOINT内遇到明确HttpError
404/409/422，先ROLLBACK TO SAVEPOINT，再持久保存原请求的rejected回执；没有部分计划或成功SO桥接。
客户端仍须核对requestId、payloadHash、replayed与HTTP状态，不能凭裸422清缓存。
未知SQL/审计/连接失败继续整体回滚、结果未知；401/403不伪装已保存领域回执。
该修复复用0035表和同一命令服务，无新迁移、业务数量限制或权限扩张。

## 历史和边界

按版本锚点加载历史；追加新版本不挤动旧页。合并各页的当时资源摘要，不能拿当前主资料名补造历史。
页面、GET投影、预览和回执无销售价、工价、裸外发价、实际完成或币种。
Server关闭/冻结边界以现有服务为准；不把本页称完整生产闭环。
仅在一次性合成PostgreSQL和私有Chromium profile验收；旧体验端口、数据卷、Browser缓存及真实账号/来源不改。
