## C0.1 engineering resolution (disposable only)

- `Dockerfile.server` now accepts only `browser | frozen | server` at build time, stamps the image authority label and runtime environment, and passes the same value into Vite. Invalid input fails the build. The Browser authority reader uses the injected build-info constant, and production startup rejects runtime/build-info mismatch. The disposable image test checks both `frozen` and `server` compiled assets against their `/build-info.json`; the default remains Browser.
- `server/maintenance-static.ts` serves only `dist/client` plus `/maintenance-health` without importing Server DB config, creating a pool, verifying migrations, syncing permissions or bootstrapping admin. `/api/*` returns 503, with no HTML fallback. It rejects DB/admin environment keys and requires the compiled frozen identity. `scripts/Invoke-Q3MaintenanceStaticHandoff.ps1` supports `-VerifyOnly` and separately confirmed `-Execute`: it binds explicit image ID/revision/build ID/time and Browser origin/port, then stops only the verified writer and starts a standalone static container from the **same image ID**, on Docker `bridge` rather than the PostgreSQL Compose network, without DB env or mounts. It re-verifies the frozen build on the same origin after handoff. It does **not** weaken `Assert-ZhixuWritersFrozen` or restart the writer automatically on failure.
- The handoff was exercised only with randomly named disposable containers and a tmpfs PostgreSQL 16 database without a host PostgreSQL port or production volume/network. This is an engineering test, **not** a real frozen deployment or proof that a particular Browser profile is authoritative. Source/rehearsal/import guards include the new static and handoff paths; a new reviewed code commit is required. The older Q3B2I-B commit `e92df9279376cd5e74f10abf95dcef2f70f687ac` must not be reused as `ExpectedImportSourceCommit` after these changes.

## C1 ordered checklist — planning only

Each item below requires a separately authorized maintenance window. Record UTC times and safe IDs, not credentials or raw customer data. Any failed condition stops the window with Browser master/settings frozen until a separately authorized recovery decision.

1. Reconfirm reviewed Git HEAD, clean guarded critical paths, exact target fingerprint, ledger `0001`–`0007` current, seven Q3 tables empty, and existing-domain aggregate/invariants. Confirm maintenance owner and no concurrent import.
2. Confirm the authoritative Browser origin/profile. Build and deploy one reviewed **frozen** image with exact `gitCommit`, `buildId`, `buildTime`, and `masterSettingsAuthority=frozen`. Record its immutable image ID. This is a deployment step, not part of C0/C0.1.
3. In that profile, close all old Zhixu tabs/windows, reopen the frozen build, and obtain the operator's explicit old-client closure attestation. Verify the live `/build-info.json` and create the Git-ignored freeze evidence using `scripts/verify-q3-frozen-build.ts` with `--origin`, `--namespace`, `--schema-version`, `--commit`, `--build-id`, `--build-time`, `--freeze-started-at`, `--operator`, `--browser-profile`, `--evidence`, and `--confirm-old-tabs-closed`. Hash the evidence file.
4. Run `scripts/Invoke-Q3MaintenanceStaticHandoff.ps1 -VerifyOnly` with **explicit** image ID/revision/build ID/time, writer/project, authoritative origin, static container name and host port. Only after PASS and separate window authorization, use its confirmed `-Execute`: stop the verified DB-writer Node container and start maintenance-static from that **same image ID** at the **same Browser origin**. Call the frozen-build verifier again after handoff. Only then inventory remaining Compose containers, background jobs and `pg_stat_activity`, and require `Assert-ZhixuWritersFrozen` PASS. Do not stop PostgreSQL. Do not proceed on an unknown DB client or static-container identity mismatch. The normal image's API healthcheck is disabled for the static container; `/maintenance-health` proves static serving only.
5. From the attested, frozen authoritative Browser profile, export one fresh standard backup through `/system-settings/data-management`. Store it outside Git-tracked paths, record capture time and SHA-256, and make it immutable for this attempt. The source must not be an older backup or a different profile.
6. Run only the canonical Preview: `npm run preview:quote-master-settings -- --backup <FRESH_BACKUP_ABSOLUTE_PATH>`. Require expected backup identity, zero `blockingErrors`, and record `sourceHash`, projection content hash, counts and warnings. Do not normalize through a second implementation. Reconfirm the file SHA-256.
7. Run isolated rehearsal with the same source and reviewed commit using `scripts/Invoke-Q3IsolatedRehearsal.ps1 -BackupFile <PATH> -ExpectedBackupFileSha256 <64_HEX> -ExpectedSourceHash <64_HEX> -ReviewedCommit <40_HEX> -EvidenceDirectory <GIT_IGNORED_BACKUPS_SUBDIR>`. Require portless/tmpfs PostgreSQL, cleanup PASS, proof JSON and its SHA-256. Any source change restarts Preview/rehearsal.
8. While Browser and DB writers remain frozen, create a **new** exact-target rollback archive using `Backup-Zhixu.ps1 -ExpectedContainerName zhixu-database -ExpectedComposeProject preparesystem -ExpectedVolumeName preparesystem_zhixu_data -ExpectedDatabaseName zhixu -ExpectedTargetFingerprint <FRESH_VERIFIED_64_HEX>`. Verify an independent copy/hash; use an isolated restore drill if required by the approved recovery plan. Never run restore during C1 without separate authorization.

Invoke `scripts/Invoke-Q3GuardedMasterImport.ps1` in **`-VerifyOnly`** mode with the exact target fields, reviewed commit, attested Browser identity, frozen build ID, fresh backup SHA/source/projection hashes, rehearsal proof SHA, freeze evidence SHA and new rollback dump/manifest SHA. ## Failure truth table

| Event | Database truth | Required action |
| --- | --- | --- |
| Fresh export, Preview or rehearsal fails | No import write | Keep Browser frozen; stop; repair only in a new reviewed attempt. |
| Guarded VerifyOnly fails | No import write | Keep Browser frozen; stop. |
| Execute transaction fails before COMMIT | Import rolled back | Keep Browser frozen; stop; retain FAILED D-091 evidence. |
| COMMIT outcome unknown | Unknown | Keep Browser frozen; no retry or restore; investigate ledger, rows and D-091 evidence. |
| COMMITTED but readback unverified | Committed, not validated | Keep Browser frozen; no retry or claim of rollback; investigate. |
| COMMITTED/readback PASS but Server deployment or smoke fails | Imported rows remain | Keep Browser frozen; do not reopen Browser writable authority or auto-restore. |

Restoring the backup or returning to Browser writable authority always requires new user authorization and a separately reviewed reconciliation plan.
