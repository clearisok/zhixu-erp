This is a planning artifact from the Q3B2I-C0 read-only preflight on 2026-09-29. It is **not** authorization to deploy, freeze, export, back up, import, or restore. ## C0 blockers to resolve and independently validate before opening C1

1. `Dockerfile.server` does not declare or pass `NEXT_PUBLIC_ZHIXU_MASTER_SETTINGS_AUTHORITY` into its Vite build. The present image and `/build-info.json` have no authority field; a `frozen` or `server` build arg would be ignored. Add an explicit builder-stage input, validate both variants in disposable builds, and bind image revision/build ID/time/authority to a newly reviewed source commit. This touches a guarded critical path: the Q3B2I-B reviewed commit `e92df9279376cd5e74f10abf95dcef2f70f687ac` cannot be reused as `ExpectedImportSourceCommit` after such a change. Rerun the isolated rehearsal and guarded tests against the new reviewed commit; do not weaken the source guard.
2. The current single `preparesystem-server-1` container serves `/build-info.json` and is also a PostgreSQL client. `Assert-ZhixuWritersFrozen` requires every non-database container in the `preparesystem` project stopped and zero other DB clients. The import wrapper requires the frozen `/build-info.json` to remain reachable at `ExpectedBrowserOrigin` during VerifyOnly and Execute. With this topology, those requirements cannot coexist. Design and validate an independent static frozen frontend endpoint that cannot write PostgreSQL, or a separately reviewed equivalent safety design. Do not simply exempt the Server from the writer guard or remove the running-build check.
3. The authoritative Browser origin and profile have not been independently attested. The current endpoint at `http://127.0.0.1:3002` is reachable, but it is not proof that its Browser profile holds the authoritative local data. The operator must identify the actual origin/profile and verify the fresh export's `origin`, `environment`, `namespace` (`zhixu.erp.local`) and `schemaVersion` (`13`). The 2026-09-22 backup is not a final source.
4. D-091 artifacts are currently local and Git-ignored, not independently durable. Before C1, approve an independent destination with confirmed access, retention, and hash verification. Never commit raw Browser backup, PostgreSQL dump, credentials, or secrets.

## C1 ordered checklist — planning only

## Failure truth table

| Event | Database truth | Required action |
| --- | --- | --- |
| Fresh export, Preview or rehearsal fails | No import write | Keep Browser frozen; stop; repair only in a new reviewed attempt. |
| Guarded VerifyOnly fails | No import write | Keep Browser frozen; stop. |
| Execute transaction fails before COMMIT | Import rolled back | Keep Browser frozen; stop; retain FAILED D-091 evidence. |
| COMMIT outcome unknown | Unknown | Keep Browser frozen; no retry or restore; investigate ledger, rows and D-091 evidence. |
| COMMITTED but readback unverified | Committed, not validated | Keep Browser frozen; no retry or claim of rollback; investigate. |
| COMMITTED/readback PASS but Server deployment or smoke fails | Imported rows remain | Keep Browser frozen; do not reopen Browser writable authority or auto-restore. |

Restoring the backup or returning to Browser writable authority always requires new user authorization and a separately reviewed reconciliation plan.

## D-091 evidence custody plan

For each attempt, keep a local Git-ignored, access-limited evidence directory containing freeze evidence, a **summary** of the fresh source identity/hash (not the raw backup in the evidence bundle), rehearsal proof, rollback manifest, D-091 import evidence and final cutover manifest. Include an index with filename, SHA-256, byte count, UTC capture time, operator and attempt ID. Copy the evidence bundle and rollback archive to a separately approved storage location, verify copy hashes from that location, and retain a second independent copy or versioned backup. Restrict access and retention according to the user's operational policy. Preserve FAILED, COMMIT_OUTCOME_UNKNOWN and COMMITTED_UNVERIFIED attempts, not only success. The existing local-only evidence is not sufficient; the destination and copy-verification procedure must be approved and tested before C1.
