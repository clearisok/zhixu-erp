后端d207已送达并三CI成功；本页面当前在隔离合成验收中，不能称已部署或人工接受。

## 唯一owner与原界面

继续复用正式Server排单路由、同一session、Foundation、生产组MasterDetail、订单池、队列、
结束弹窗、差异预览及历史抽屉，不挂载Browser repository、不迁入旧完成量、不增导航或重设计密度。
组摘要显示待执行条数与累计已登记完成；订单区并列计划/已完成/待执行，队列逐条区分“尚未登记”与真实零。
订单、计划、实际与需求的十进制字符串保持精确，不经JS number汇总。

“登记进度”输入累计完成量、实际开工日期、进行中/已结束及说明；“结束排单”仍先确认真实值。
首次数量为空，日期一律不取计划或今天。超计划只警告，允许实际零和大数/小数。
减少完成量、更正已有日期、重开或更正已取消记录需原因，复用后台纯规则而非第二套计算。
归属字段与单价、币种、actor、服务器版本不能通过执行表单提交。已有执行头后，计划表单锁定执行方/颜色，
即使后来更正为零仍保持；取消保留产出和历史，剩余任务新增Assignment。

## 仅登记与明确联动

本单登记只要求order.view、schedule.view、schedule.complete；预览与提交、回执均由后台fresh鉴权。
它不依赖非必需的整组读取或当前主资料仍启用。只有用户明确点击“结束并预览后续排期”才读取队列，
并要求schedule.edit、有效内部排单和明确实际结束日期；有编辑权限也不能使本单登记多一个前置。
联动失败保留表单，不自动降级成另一次写入；401/失效lease不吞掉。不联动则只登记本单。

第二步逐项展示本单前后数量/状态/日期及后续款号、订单号、颜色与日期差异。用户确认后，同一原请求
同时保存本单实际版本和后续计划版本；前序、固定、已执行和只读订单不动，产出不搬，客户交期不改。
本单及队列的版本/CAS、完整预览指纹与不可变历史继续由同一事务服务核对。无差异不重复保存。

## 同一未决槽与身份隔离

沿用 `zhixu.server.production-plan.pending.v1.<public-user-id>` 和原schemaVersion=1四字段包装，
只前向增加record_execution命令类型。旧计划原字节可读；计划与执行共享每actor/tab一个槽，
任一未知命令未核对前不能创建另一命令。旧程序不能理解的新命令会阻断，不会删除或覆盖。
不改localStorage/IndexedDB/Browser namespace、Seed、备份或业务存储。缓存仅用户主动命令，不存密码、
令牌、金额、来源凭据或服务端原文。最多1MiB，写入并读回成功才POST，缺存储不以内存冒充恢复。

预览、hash、POST、GET及响应解码都绑定完整session对象lease。换人或A→B→A后旧200/401不能
确认新缓存、退出新会话或更新新视图。规范化JSON和WebCrypto SHA-256复用原后端字节规则。
丢回执、错hash、裸错误、撤权、损坏/未来记录均保留原请求且不自动POST；只在同一session明确GET
为unknown之后，允许人工重试同一UUID/全部原内容。known回执验证requestId/hash/身份、事实、版本、
HTTP状态与replayed后才清精确原槽。成功后另读当前投影，旧回执不当成当前订单事实。
不存在的回执仅证明未找到本用户原编号，不代表已授予该命令写权限；人工重试仍重新核实全部领域权限。
未保存/处理中/未知状态继续登记既有导航保护；域拒绝保留输入，重新读取实际版本后必须重新预览。

## 读取与历史

扩展原生产客户端的非金额白名单，order/queue执行映射按原Assignment/SO/执行方/颜色/资源hash核验，
多余金额/令牌/未知原文不投影。实际head保留独立版本，计划版本以后变更不伪造旧采用时间。
执行历史使用自己的asOfVersion和50条分页，后续追加不挤动已打开页；不借计划版本作执行锚点。
已取消/冻结记录仍可查看历史；当前冻结边界仍阻止写入。事件时间按北京时间展示，不用当前名称补造历史。
没有实际记录显示“尚未登记”，不创建零值head或以计划数量代替产出。

新浏览器验收仅在独立一次性PG、loopback HTTP和私有Chromium profile进行；旧目标环境未升级。
本页不提供成衣出货、物流、关账、成本、销售价、工价或换汇；这些未完边界不能据本页通过而升级能力标签。
