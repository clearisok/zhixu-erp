核实日期：2026-10-12；main：5215ef75510e4b55ef69b1ae1508816b80fda110（PR97已合并）。本文是 **AI 提案和执行 Gate**，不是已部署声明或执行授权。证据见[现场预检](../tasks/completed/2026-10-12-ningbo-readonly-preflight.md)。入口、镜像、schema、Source、范围或人工验收变化时更新；发布前重新读取 GitHub main 和实际运行态。

## 目标与已决定边界

尽快让管理员、管理者、报价经理、物控经理、生产经理、财务经理进入一个可信 session 系统，先完成真实报价闭环；现有 UI 和商业金额边界保持。首轮从独立空业务账本开始；管理员自行创建真实成员。PR97 的角色功能已实现/合并/合成测试，但真实部署和人工验收尚未发生。

“艾诺科全部可见”指所有已登录团队可读已授权采集内容，包括来源采购价；不代表已经接通 Linux Source，也不等于开放订单、物料、生产、关账路由。Quote-first 试用与后续受控 Ainuoke Source 是两条有依赖但可分阶段交付的任务。若首日必须看到艾诺科合同，须先完成 Source 独立 Gate；不能把静态角色预设当作合同已经可见。

## 版本晋升选择

| 方案 | 工作与风险 | 建议 |
| --- | --- | --- |
| 原地升级旧 zhixu-staging | 需授权 0008–0011、管理员、authority、存储和入口修复；旧配置与新发布容易混淆；代码回退不等于 DB 回退 | 目前不选。主表为空不构成覆盖授权 |
| 独立新 Compose/DB/卷/候选入口，通过后切域名 | 多一套配置，但目标可精确锁定，可保留旧入口/镜像/卷，符合 D-096 | **推荐**；把已有 ops/quote-trial 的校验/备份思想用于 Linux，不照搬 Windows TLS 配置 |
| Preview 与旧业务共库、直接替换 legacy 镜像 | 数据模型、版本、账号及测试写入边界冲突 | 不可采用 |

候选命名建议 zhixu-ningbo-v1；新数据库及新命名卷，独立 backend 网络。应用仅绑定 loopback，候选端口可选 3003（预检未监听，发布前重新检查；目前未占用/预留）。公网保持 Cloudflare Tunnel 架构；是否 HTTP loopback origin 或内部 HTTPS，先确认当前 ingress，再确定配置，不擅自新增代理。候选测试可以先用受控入口，不要求多买域名。

对象存储必须形成与旧环境隔离的命名空间、授权和备份归属。先检查现有 storage adapter 是否支持拟议 prefix；不支持则使用独立 bucket 或另立最小工程修改，不能只在文档写“隔离”却仍生成共享 key。新 DB 不恢复旧 dump，不读 Browser namespace 兜底。

## 最值得立即创建的下一个 PR

建议分支 **chore/ningbo-release-candidate**，只提交 Linux 候选发布配置、脱敏 env 模板、明确区分只读/写入的工具及隔离测试。预计 1–2 个工程工作日，假设现有 Docker/测试依赖可用、COS 权限可私下配置、Cloudflare 路由能核查；它不是上线日期承诺。

交付内容：
1. 复用 Dockerfile.server；锁定源码完整 SHA 和镜像 digest/ID。显式 Quote=server、masters=server、writer=writable、identity=session；构建标签、build-info、runtime 一致，不允许默认 browser 或 local-single-user 混入外网。
2. 独立 Compose project/网络/卷/DB，app 非 root，DB 无公网端口；密码不进模板，配置文件限制权限。已有生产 workflow 保持不动，候选操作入口必须显式目标。
3. 只读 preflight 只做元数据/配置验证；init/migrate/bootstrap/start/switch/backup/restore 明确为有副作用的操作，默认不执行。现有 server:start 会写权限目录，不能放入只读路径。执行入口防误指向 zhixu-prod、zhixu-staging、18443/18444。
4. Linux 一次性合成环境验证 0001–0011 空初始化、完整 session/Cookie/Origin、六角色、权限变化/撤销、刷新持久化、报价/附件/导出、CSS 加载和现有响应式布局；每项绑定精确候选 SHA。
5. disposable PG + 独立测试对象存储完成备份/恢复 readback 与故障回退演练。真实 COS PUT/DELETE、真实管理员/DB 启动和域名切换仍须单独授权。
6. 更新候选 manifest、运行步骤/回退步骤、PR 证据与 CURRENT_STATE；CI 通过后复审，不自动合并或部署。

## 执行顺序与停止条件（尚未执行）

1. **工程准备**：下一 PR 在独立 worktree 完成配置/合成演练；只读补查 Cloudflare 配置。任何 schema checksum 漂移、目标重名/共库、dirty 未知、authority不一致都 STOP。
2. **冻结候选**：PR 合并后重新核实 main，记录源码SHA、镜像ID、迁移清单hash、compose/env非秘密配置hash、目标project/DB/volume/origin/storage归属。发布工程产物不等于运行态已部署。
3. **明确真实执行授权**：给用户具体候选、目标、会改哪些系统文件/新DB/账号、旧系统保留方式和回退条件。密码由用户在私密文件/交互配置，聊天/GitHub不收集。
4. **授权后初始化隔离目标**：只对新库执行迁移和显式管理员初始化；空表核验、最小role catalog、session登录、只读匿名拒绝、权限和对象存储真实检查。不得挂载旧DB卷或共享旧bootstrap账号。
5. **受控试用**：管理员私下创建成员；合成账号不进入正式账本。外网登录、旧布局截图、报价闭环、附件哈希、导出和角色矩阵签收。物控/生产不应看到未授权织序金额；获准的Ainuoke展示仍须Source Gate。
6. **晋升**：记录人工验收后单独批准域名切换/扩大使用；保留原origin配置和镜像。检查缓存不让旧HTML与新asset混用，API与build-info必须同一候选；真实业务允许写入时间需要记录。
7. **交付记录**：源码实现、合并、镜像构建、真实部署、人工验收、Source激活六列分别更新；记录未跑项，不把数据为空写成已清库。

## 回退

- 切入口前失败：停止候选晋升，保留候选证据；旧服务/卷不动。不得为“恢复干净”删库或改已有数据。
- 切入口后但尚无新业务写入：可在另行授权下恢复先前已确认 origin，验证旧版本；保留候选DB/对象，不自动删除。
- 已有新业务写入：先受控维护/停止继续写入，保全当前 DB、对象和操作日志；按已验证兼容性选择回退应用镜像或前向修复。旧系统不会自动拥有新账本数据，不可把切回旧页面称为无损业务回退。
- migration 不自动 down；DB restore 不是镜像 rollback。恢复只能在明确选定的独立目标、备份hash/对象归属通过、用户授权后操作；避免恢复覆盖唯一新业务副本。初版无同账本旧版本时，优先维护+前向修复。
- 回退完成标准包括版本/health、认证、数据和附件读回、权限以及用户确认；只看到容器healthy不算完成。

## 需要用户提供的最少信息

工程准备和只读主机检查可以继续自主完成。到真实上线前才需要：
- Cloudflare Public Hostname 的 origin 地址以及相关 Access/WAF 策略的只读结果，或授权进入已登录控制台核查；不提供Tunnel token。
- 私密配置首个系统管理员与COS最小权限凭据的操作人，以及计划试用时间；无需聊天发送密码。
- 备份/故障通知接收人、旧宁波系统保留周期。建议首轮保留旧环境直至新账本恢复演练与人工验收完成，之后清理另行授权。

首批真实姓名/账号名单由系统管理员在新系统内创建；已批准六角色不再重复讨论。首次建议只请管理员和报价经理完成一个报价闭环，再放大到其余角色，减少上线等待而不弱化金额保护。
