## 一、全局视觉规范

| 项目 | 实际观察 |
| --- | --- |
| 主色 | 深绿 `#175C4B`；深色侧栏约 `#15251F`；少量金棕强调约 `#DDB27E` |
| 背景色 | 页面米灰 `#F3F2ED`，内容卡片白色 `#FFFFFF`，表头接近 `#FAFBF9` |
| 正文色 | 主文字约 `#15211E`，次级文字多为灰绿 `#74807B` / `#9AADA5` |
| 字体 | 正文为 Inter、Noto Sans SC、Microsoft YaHei；一级标题使用 Georgia、Songti SC |
| 字号 | 正文通常 12–14px；表头约 10–13px；一级标题约 33px |
| 行高 | 多数由浏览器 normal 控制；表格表头约 43–50px，高密度列表行约 44–56px |
| 输入框 | 常见外框高度 42–45px；部分紧凑表格内输入框更低 |
| 按钮 | 导航按钮常见 42px 高；主操作按钮多为中等尺寸，文字与图标并用 |
| 圆角 | 输入框约 7–10px；卡片、弹窗和分段容器多为 12–18px |
| 留白 | 页面标题区留白充足，但宽表、长表单和详情页内部留白不一致 |
| 信息密度 | 列表页中高密度；报价和订单详情为极高密度；窄屏自动转卡片，但会牺牲横向比较能力 |

### 表格风格

- 浅色表头、细分隔线、状态标签与行内操作构成主要模式。
- 报价中心、订单中心和生产组队列存在横向滚动；关键列表检测到粘性列或粘性表头。
- 基础资料表格通常可横向滚动，但未发现固定列。
- 本次可见数据量均未出现分页控件，系统更像是当前数据量下的单页滚动。

## 二、全局交互模式

### 查询

- 页面顶部通常为即时搜索框，并配合 0–3 个下拉筛选。
- 没有统一的“查询 / 重置”按钮；多数页面输入后即时过滤。
- 搜索框的标签、占位文字和容器样式不完全一致。

### 新增

- 核心业务使用独立工作区页面：新建报价、新建订单。
- 基础资料与系统设置多使用居中弹窗，底部固定“取消 + 保存”。
- 空表格状态会再次显示新增按钮，造成同页重复主操作。

### 编辑

- 基础资料通过行内“编辑”打开与新增相同结构的弹窗。
- 报价和订单详情直接呈现可编辑表单，并通过顶部或局部保存按钮提交。
- 多处存在“保存草稿”“保存”“保存设置”等相近但层级不同的保存入口。

### 删除

- 基础资料使用行内文字按钮；报价详情存在“删除报价”。
- 删除入口与编辑入口距离很近，危险操作的视觉层级偏弱。
- 本次审计未触发任何删除确认。

### 导出

- 报价中心支持批量导出；报价详情支持单张导出。
- 模板设置提供下载、试导出；数据管理提供测试数据导出。
- 本次未实际下载，避免产生非审计必要的文件副作用。

### 查看详情

- 报价与订单从列表进入完整工作区页面。
- 生产排单从生产组卡片进入单组队列。
- 操作日志与用户权限采用原页内展开，减少页面跳转，但会显著拉长页面。

### 弹窗

- 弹窗普遍包含英文眉题、中文标题、说明、右上角关闭、底部取消/保存。
- 弹窗字段清晰，但在小视口中容易形成长滚动。
- “生产与运输”所有不同实体共用“编辑生产与运输设置”标题，辨识度不足。

### 页面跳转

- 左侧一级导航固定；基础设置和系统设置通过弹出菜单进入二级页面。
- 报价、订单使用列表 → 工作区 → 返回列表模式。
- 空白新建订单离开时会出现“未保存修改”拦截，支持继续编辑、不保存返回、保存返回。

### 批量操作

- 明确观察到报价中心“批量导出”。
- 未观察到列表复选框、跨页选择或统一批量操作条，批量能力较弱。

## 三、旧系统值得继承的部分

1. 报价、订单、生产排单之间的业务链路清晰，详情页能同时看到上下游状态。
2. 报价版本、价格版本、客户确认、订单价格与数量历史均被显式保留，业务可追溯性强。
3. 基础资料采用“系统默认 → 品牌 → 客户业务员”的继承逻辑，并在文案中解释回退规则。
4. 操作日志提供业务化描述、前后值与技术详情，审计价值很高。
5. 报价和订单列表允许用户配置列及列宽，适合高频 ERP 用户。
6. 生产排单把物料齐套、运输、生产组队列和订单执行联系在一起，业务模型值得保留。

## 四、旧系统明显落后的部分

1. 一级标题使用大号衬线体，视觉气质强但占据过多垂直空间，不利于 ERP 高频操作。
2. 详情页信息过长，报价与订单把编辑、历史、附件、排单和关账集中在单页，定位成本高。
3. 宽表依赖横向滚动；固定列策略不统一，窄屏转卡片后又丢失横向对比能力。
4. 主操作重复：基础资料页在标题区和空态/列表区重复显示新增按钮。
5. 保存入口层级不统一，存在“保存草稿 / 保存 / 保存设置 / 保存并返回”等相近表述。
6. 危险操作与普通操作距离过近，缺少一致的危险色、二次确认语义和权限提示。
7. 搜索、筛选、状态标签、空态和弹窗标题缺少跨模块统一规范。
8. 操作日志与权限详情使用无限纵向展开，缺少分组折叠、锚点和信息摘要。

## 五、现代 ERP 的信息密度与操作习惯建议

- 保持“列表高密度、详情分区高密度”的总体方向，不建议改成低密度营销型界面。
- 列表默认行高建议 40–44px，允许用户切换紧凑/标准密度；表头 40–44px。
- 固定首个业务识别列与末尾操作列，横向滚动时持续显示列名、对象编号和关键操作。
- 报价/订单详情改为“概览 + 分区标签/锚点 + 右侧关键指标摘要”，历史和附件按需展开。
- 保留桌面宽表，同时为窄屏提供专门的任务卡片视图，而不是简单隐藏字段。
- 统一页面头部：标题、说明、主要操作、次要操作；同一层级只保留一个主按钮。
- 统一保存模式：页面级保存固定在同一位置，局部保存只用于独立子对象并明确作用域。
- 保留可配置列和列宽，并增加保存视图、恢复视图、共享角色视图。
- 对删除、恢复默认、重置数据、切换账号等高风险操作采用一致危险样式和影响说明。

## 最值得优先重新设计的 5 个页面

1. 报价详情工作区：信息量最大、保存层级最多、成本宽表与版本关系复杂。
2. 订单详情工作区：业务执行、价格/数量历史、排单、关账、物料运输全部堆叠在单页。
3. 生产排单：总览、队列、异常、物料运输之间需要更清晰的任务流和状态解释。
4. 用户权限：43 项权限长列表不利于角色对比、批量配置和异常权限识别。
5. 生产与运输：五类基础设施共用一页与通用弹窗，实体边界和依赖关系不够直观。
