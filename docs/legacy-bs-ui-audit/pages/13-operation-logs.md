# 13 操作日志

![操作日志](../screenshots/13-operation-logs.png)

## 页面信息

1. 页面名称：操作日志。
2. 菜单位置：系统设置 / 操作日志。
3. URL：`/system-settings/operation-logs`。
4. 主要用途：按用户、模块、动作和日期查询追加式业务审计记录，并查看字段前后值。
5. 主要角色：系统管理员、审计人员、业务主管、问题排查人员。
6. 顶部筛选：全文搜索（业务对象、操作人、动作、款号或成本行）、用户、模块、操作、开始日期、结束日期。
7. 主要按钮：每条记录的“技术详情”。
8. 主列表字段：时间、操作人、账号、业务动作、业务对象、模块；展开后按业务子对象展示字段、变更前、变更后。页面采用日志卡片而非标准表格。
9. 滚动与分页：长列表纵向滚动；本次可见 41 个技术详情入口，未观察到分页。

## 技术详情展开

![操作日志技术详情](../screenshots/13d-operation-log-technical-detail.png)

10. 点击技术详情在原日志卡片中展开。
11. 展开内容因动作而异，可包含对象编号、价格版本、数量、币种、日期，以及逐字段变更前/后值；没有额外保存按钮，纯只读。
12. 典型流程：输入对象或款号 → 按模块/动作/用户/日期缩小范围 → 找到日志 → 展开技术详情 → 对比前后值并追溯关联对象。
13. UI/UX 问题：日志数量多时无限纵向列表扫描困难；多条展开会显著拉长页面；“技术详情”实际包含业务可读信息，命名偏技术；缺少导出、固定摘要列、对象直达链接和分页/虚拟滚动提示。
14. 值得保留：业务化动作名称；操作人和对象上下文；追加式记录；字段级前后值；覆盖报价、订单、排单、关账和基础设置。
15. 建议重新设计：使用时间线或虚拟化表格；详情改右侧抽屉并保留列表位置；增加对象直达、复制事件 ID、导出筛选结果；默认显示业务摘要，JSON/技术元数据作为二级标签。
